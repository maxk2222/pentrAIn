# Docs media pipeline

Everything under `docs/assets/screenshots/` and `docs/assets/gifs/` is generated by
`capture.py` — a Playwright + Pillow script that drives the real UI against the
**MockProvider** dev stack. No ffmpeg, no Proxmox, no real credentials.

> [!WARNING]
> Never point the capture at a production backend. It completes the setup
> wizard, creates/aborts sessions and posts demo coach messages. The default
> database is a throwaway `/tmp/pentrain-docs.db`.

## Setup

```bash
python3 -m venv docs/media/.venv
docs/media/.venv/bin/pip install -r docs/media/requirements.txt
docs/media/.venv/bin/python -m playwright install chromium
```

## Dev stack on dedicated ports

Keep captures away from a running dev instance (and its real `pentrain.db`):

```bash
# backend — mock engine + disposable DB + service token for coach injection
PENTRAIN_ENGINE_MODE=mock \
PENTRAIN_CONTENT_DIR=$PWD/content/packs \
PENTRAIN_DATABASE_URL=sqlite+aiosqlite:////tmp/pentrain-docs.db \
PENTRAIN_APP_SECRET=docs-capture-secret \
PENTRAIN_COACH_SERVICE_TOKEN=docs-coach-token \
  backend/.venv/bin/uvicorn app.main:app --app-dir backend --port 8010

# frontend — vite config that proxies /api and /ws to :8010
cd frontend && npx vite --config vite.docs.config.ts   # serves :5199
```

`frontend/vite.docs.config.ts` exists solely for captures — it must live in
`frontend/` so node module resolution works, and it sets a modern build target
because `@novnc/novnc` uses top-level await.

## Capture

```bash
cd ..   # repo root

# all page screenshots -> docs/assets/screenshots/
docs/media/.venv/bin/python docs/media/capture.py shots \
    --app http://localhost:5199 --api http://localhost:8010

# all walkthrough GIFs -> docs/assets/gifs/
docs/media/.venv/bin/python docs/media/capture.py gif all \
    --app http://localhost:5199 --api http://localhost:8010

# a single GIF
docs/media/.venv/bin/python docs/media/capture.py gif flag-solve \
    --app http://localhost:5199 --api http://localhost:8010

# just (re)seed the demo session + coach chat
docs/media/.venv/bin/python docs/media/capture.py seed \
    --app http://localhost:5199 --api http://localhost:8010
```

## What the script does

| Step | Mechanism |
|---|---|
| Login / setup | `POST /api/auth/login` (first call adopts the password on a fresh DB), then `POST /api/setup/complete` if needed |
| Demo session | `POST /api/sessions` for `linux-t1-first-foothold`, waits for `ready`, activates |
| Coach chat | Injects welcome/hint/suggestion/action-report messages via the coach service endpoints (`/api/coach/message|stream|suggest`) using `PENTRAIN_COACH_SERVICE_TOKEN` |
| Flag submission | Reads expected secrets straight from the sqlite DB (`expected_flags` table — mock mode never writes into guests) and types them into the UI |
| Screenshots | Full-page/viewport PNGs at 2× device scale |
| GIFs | Viewport frames at ~5 fps, stitched with Pillow (`quantize(255)`, ~250 ms per frame) |

> [!NOTE]
> The console area shows the MockProvider placeholder ("Mock engine — no real
> Kali console"). That is honest: captures document the UI, not a live range.
> Docs that embed the GIFs state this explicitly.

## Conventions

- Screenshots are numbered in walkthrough order (`01-setup` … `12-settings`).
- GIF names are referenced from docs — rename only together with the docs.
- Keep `QUEST = "linux-t1-first-foothold"` — it is the smallest tier-1 quest and
  its briefing text is written for a general audience.
- The capture never stores the token it gets; nothing in `docs/assets/` may
  contain credentials, hostnames of real infra, or local paths.
